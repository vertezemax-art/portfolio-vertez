# Портфолио Максима Вертезе

Сайт на Next.js (App Router), Tailwind CSS и Sanity CMS. Публичная часть показывает только кейсы со статусом `published`; черновики остаются в Sanity Studio.

## Локальный запуск

1. Установите зависимости: `npm install`.
2. Скопируйте `.env.example` в `.env.local`.
3. Создайте проект в [Sanity Manage](https://www.sanity.io/manage), внесите `NEXT_PUBLIC_SANITY_PROJECT_ID` и при необходимости `NEXT_PUBLIC_SANITY_DATASET`.
4. Выполните `npm run dev` и откройте `http://localhost:3000`.

Пока переменные Sanity не заполнены, сайт показывает 3 демонстрационных заполнителя. Это позволяет сразу настроить дизайн; реальные материалы не подменяются вымышленными данными.

## Управление кейсами

Откройте `/studio` и войдите через Sanity. В Studio создайте документ «Кейс», заполните поля и:

- оставьте `Статус на сайте` = «Черновик», чтобы скрыть материал;
- выберите «Опубликован» и поставьте дату публикации, чтобы показать его на сайте;
- используйте стандартную кнопку Publish в Studio, чтобы зафиксировать изменения.

Доступом управляет владелец проекта в Sanity Manage → Project → Members: публичной регистрации нет, а приглашать новых редакторов может только владелец проекта. Авторизация и права проверяются Sanity на серверной стороне Studio; пароли и токены не попадают в код сайта. Не добавляйте токены в переменные с префиксом `NEXT_PUBLIC_`.

### Быстрое наполнение учебными кейсами

1. В Sanity Manage откройте нужный проект → **API** → **Tokens** → **Add API token**.
2. Дайте токену роль **Editor**, скопируйте его один раз и добавьте в `.env.local` как `SANITY_API_TOKEN`.
3. Укажите там же `NEXT_PUBLIC_SANITY_PROJECT_ID` и `NEXT_PUBLIC_SANITY_DATASET`.
4. Установите зависимости (`npm install`) и выполните `npm run seed`.

Скрипт подключается к API через `@sanity/client`, без Sanity CLI, и создаёт опубликованные TaskFlow, WeatherHub и Morning Brew. У каждого есть готовые тексты для всех полей кейса. Повторный запуск безопасен: `createIfNotExists` пропустит уже созданные документы с идентификаторами `seed-case-…`; остальные кейсы не затрагиваются.

Это учебные работы, поэтому в текстах явно отмечен их статус — они не содержат выдуманных клиентских метрик. В Studio можно заменить их обложки, отредактировать материалы или снять с публикации.

## Деплой на Vercel

Импортируйте репозиторий в Vercel, добавьте значения из `.env.local` в Project Settings → Environment Variables и задеплойте. После этого добавьте адрес сайта в CORS Origins проекта Sanity. Если dataset закрытый, добавьте `SANITY_API_READ_TOKEN` с доступом Viewer: он используется только при рендеринге на сервере. Для немедленного обновления сайта после публикации можно настроить Sanity webhook на Vercel Deploy Hook.

## Детали интерфейса

«Мои кейсы» — настоящая ссылка-якорь; у неё видимый фокус, а плавная прокрутка автоматически отключается при `prefers-reduced-motion`. Карточки открывают модальное окно с полным описанием. Оно доступно с клавиатуры, закрывается по Escape и возвращает пользователя в контекст страницы.
